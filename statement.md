# Project Statement

## Problem Statement
Students often need a simple way to maintain academic records, enter subject marks, calculate results and generate a readable report. Manual calculations and scattered records can cause mistakes and make result management inconvenient.

## Scope
The system manages basic student information and academic marks. It supports record creation, searching, updating marks, result calculation, deletion and report generation. It is intended as a small academic management application and is not a replacement for an institutional student information system.

## Target Users
- Students learning programming
- Faculty for small classroom demonstrations
- Academic project evaluators

## High-Level Features
1. Student record management
2. Marks management
3. Result analysis
4. Report generation
5. Data validation and persistent JSON storage

## Functional Modules
- Student Management
- Marks Management
- Result Analysis
- Report Generation

## Non-Functional Requirements
- Usability: menu-driven interface with clear messages.
- Reliability: persistent JSON storage and validation.
- Maintainability: separate Python modules for each responsibility.
- Error Handling: invalid marks, duplicate roll numbers and missing students are handled.
- Performance: suitable for small classroom datasets.
- Resource Efficiency: lightweight local JSON storage.

## Design Artifacts
Architecture, workflow, use case, sequence and component/class design are documented in the project report.
